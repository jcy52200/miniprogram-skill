# 微信小程序开发避坑与体验优化指南

## 核心架构特性与差异对比

微信小程序既不是纯原生应用（Native App），也不是标准的单页 Web 应用（SPA），其底层基于**双线程模型**（AppService 逻辑层与 WebView 渲染层）。

| 维度 | Web 单页应用 (SPA) | 原生应用 (Native) | 微信小程序 |
| :--- | :--- | :--- | :--- |
| **运行环境** | 单一浏览器线程 (DOM/JS 共享) | OS 原生虚拟机 / 运行时 | 双线程（JavaScriptCore/V8 + 多 WebView） |
| **DOM 访问** | 支持直接操作 `window` / `document` | 不适用 | **完全禁止访问 DOM**，仅能数据驱动 |
| **通信成本** | 进程/上下文内直接调用，几乎为 0 | 原生内存通信 | **跨线程通信 (`evaluateJavascript`)，高频传输易卡顿** |
| **生命周期** | 浏览器事件驱动 (`load`, `unload`) | Activity / UIViewController | App、Page、Component 三层独立生命周期 |
| **网络约束** | 受 CORS 同源策略限制 | 依赖系统权限 | **强制 HTTPS / WSS，需在后台预先配置合法域名白名单** |

## 必须区分的“小程序特有约束”

### 1. 双线程通信与 setData 瓶颈
- **避免高频通信：** `setData` 并非瞬时完成，数据需序列化为 JSON 字符串后经 Native 层中转写入 WebView。
- **避免传输冗余字段：** 仅传递页面 WXML 所绑定的响应式字段，不要把完整的后台接口响应体（如包含十几个未使用属性的 Object）直接塞入 `setData`。
- **使用路径更新语法：** 针对数组或嵌套对象的单项修改，采用 `this.setData({ ['list[0].status']: 1 })`，避免拷贝并全量回传整个大数组。

### 2. 包体积与分包机制
- **体积限制：** 单个主包大小不能超过 **2MB**，整包最大上限通常为 **20MB**。
- **分包策略：**
  - **主包瘦身：** 主包仅保留 TabBar 页面、公共组件、核心逻辑与必要图标，其他所有独立业务模块必须拆入 Subpackages。
  - **分包预下载：** 在 `app.json` 中配置 `preloadRule`，当用户进入特定主页面后，静默预载下一步可能访问的子包。
  - **独立分包（Independent Subpackage）：** 针对秒杀、活动推广、分享落地等深链接页面，配置独立分包，用户打开时无需加载主包。

### 3. 原生组件层级与同层渲染 (Same-Layer Rendering)
- `<video>`、`<canvas>`、`<map>`、`<textarea>` 等早期为 Native 视图覆盖，存在最高层级（`z-index` 无效）的穿透问题。
- 目前主流版本已支持同层渲染，但在复杂层叠、透明度、CSS `transform` 动画及弹窗浮层遮盖时仍需实机校验，必要时使用 `<cover-view>` 或在弹层弹出时动态隐藏原生组件。

### 4. 路由层级栈限制
- 小程序页面栈最大深度限制为 **10 层**。
- 业务流转中严禁无脑使用 `wx.navigateTo`。对于表单步骤流、支付成功后的重定向，应主动结合 `wx.redirectTo`，返回核心主链路时使用 `wx.navigateBack` 或 `wx.switchTab`。

## 显著提升体验的关键实践

### 1. 首屏渲染与加载体验
- **首屏骨架屏（Skeleton Screen）：** 借助微信开发者工具生成骨架屏代码，替代传统的居中全局 Loading 动画，缓解白屏焦虑。
- **静态资源外置：** 本地项目严禁存放大图与音频素材。图片资源一律上 CDN，并按需追加 WebP 格式转换参数与尺寸裁剪参数。
- **数据预拉取与初始缓存：**
  - 利用小程序的**周期性更新**与**数据预拉取**能力，在小程序冷启动前由微信后台预取数据。
  - 采用 **Stale-While-Revalidate** 策略：进入页面优先展示 `wx.getStorageSync` 的旧缓存，静默发起网络请求，数据返回后再平滑更新 UI。

### 2. 交互与滚动流畅度
- **按需启用 WXS（WeiXin Script）：** 处理与手势紧密相关的拖拽、吸顶跟随、视差滚动、卡片滑动等效果时，禁止在 Page 的 JS 中高频监听 `onPageScroll` 并频繁 `setData`。将逻辑移至 **WXS** 中直接在渲染层响应，避免双线程通信丢帧。
- **长列表虚拟滚动：** 超过 100 阶的长流列表（如电商瀑布流、动态流），必须引入虚拟列表（Virtual List）组件，动态回收可视区域外的 DOM 节点，防止内存溢出导致页面崩溃或白屏。
- **按需懒加载图片：** 图片标签统一配置 `lazy-load` 属性，仅当图片即将进入可视视口时再触发网络请求。

### 3. 设备适配与原生对齐
- **安全区域适配（Safe Area）：** 针对各类异形屏与底部手势条，在 CSS 中合理利用环境变量，避免核心操作区或吸底按钮被手势栏遮挡：
  ```css
  .safe-bottom-area {
    padding-bottom: constant(safe-area-inset-bottom); /* iOS < 11.2 */
    padding-bottom: env(safe-area-inset-bottom);      /* iOS >= 11.2 */
  }
  ```
* **自定义导航栏对齐胶囊按键：**
若隐藏系统默认 NavigationBar，必须通过 `wx.getMenuButtonBoundingClientRect()` 动态获取右上角胶囊按钮的 `top`、`height`、`right`，精准计算并留出占位间距，防止不同机型出现视觉重叠或布局错位。
* **点击态反馈：** 为可交互容器（按钮、列表项、卡片）配置 `hover-class`，提供即时的背景变暗或透明度微调，消除点按延迟感。

### 4. 容错与无感授权

* **隐私与权限阶梯式索取：** 坚决禁止一启动就弹窗要求获取手机号、定位或相册权限。仅在用户触发具体功能分支时，先提供操作提示说明，再发起对应的权限请求。
* **网络异常与空状态处理：** 为所有核心页面配置标准化的“无网络”、“加载失败重试”以及“暂无数据”轻量反馈卡片，提供明确的可恢复入口。
